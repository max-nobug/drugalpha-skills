# Vault 文档模板

用 [模板目录](../assets/templates/) 中的 Markdown 生成新文档。先读现有文件，已有文档只按确认范围增补。按模板用途填写 {{占位符}}。未知的属性整项省略，纯说明或示例行在填写后去掉。跟踪页暂无内容时可以保留空标题，等待后续证据。未启用公司资料入口或药物清单时，省略对应的可选链接行。

| 模板 | 生成位置与使用时机 |
| --- | --- |
| [Vault 规则](../assets/templates/AGENTS.template.md) | 第 5 步为新库生成 `Vault/AGENTS.md`。第 7 步将用户确认的入口、原件处置和维护选项补入同一文件，第 8 步复用。已有规则文件时按键义合并。 |
| [公司资料入口](../assets/templates/company-entry.md) | 第 5 步按已选架构生成 `公司/<公司名>资料入口.md`，第 8 步同步相关导航。 |
| [投资逻辑与核心跟踪变量](../assets/templates/key-driver.md) | 第 5 步生成 `公司/key-driver.md`，AI 根据现有证据写入投资逻辑和跟踪变量。第 6 步按[生成规则](drug-notes-and-maintenance.md#投资逻辑与核心跟踪变量生成规则)分类并排序，补齐变量、验证条件及出处，第 7 步验收。第 8 步创建获准公司的目录时同步建文件，随本批归档写入投资逻辑、跟踪变量及出处。对已有投资逻辑、核心变量或验证条件的实质调整，同批提交具体改文，经用户确认后写回。 |
| [核心变量变化记录](../assets/templates/notes.md) | 第 5 步生成 `公司/notes.md`，第 6 步按披露日期补齐可核实的核心变量历史变化，第 7 步验收。第 8 步归档时由 AI 同批写入可核实的实质变化，新公司目录获准创建时同步生成跟踪笔记，随本批归档填充。 |
| [公告、研报和纪要来源笔记](../assets/templates/source-note.md) | 第 5、6、8 步在归档目录生成与原件对应的来源 Markdown。资料类型按实际填写。按 PDF 实际页重复页面段。Word 或演示稿按原件换成章节、页或幻灯片等稳定定位。 |
| [Excel 模型说明](../assets/templates/model-note.md) | 有检索需要时，在 `模型/` 生成与工作簿对应的说明，引用保留在 `模型/_原件/` 的工作簿。 |
| [药物清单](../assets/templates/drug-list.md) | 启用药物目录后生成 `公司/药物/药物清单.md`。表格优先使用转义的短显示名，链接目标使用完整 Wiki 路径。模板附填写示例。详见[药物清单规则](drug-notes-and-maintenance.md#用-drugalpha-mcp-建清单)。 |
| [单药笔记](../assets/templates/drug-note.md) | 按已确认范围生成 `公司/药物/<药物名>.md`。填有证据的别名。可追溯的「后续催化」在「关键研发证据」上方。 |
| [专题笔记](../assets/templates/topic-note.md) | 用户选择建立专题时使用。 |
| [批次和验收记录](../assets/templates/batch-record.md) | 第 6、7、8 步交付统计或需要留档时使用。保存位置按本库约定。 |

`AGENTS.md` 是给 Agent 读取的普通 Markdown，保存用户已经确认的本库设置。未确认的选项标明「待确认」，尚未启用的选项写「未启用」。不同客户端是否自动读取该文件取决于客户端设置。日常调用时可在提示里明确要求先读 Vault 根目录的 `AGENTS.md`。
