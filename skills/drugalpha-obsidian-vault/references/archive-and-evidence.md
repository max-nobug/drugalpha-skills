# 归档与证据规则

用于第 5–8 步。原件保存证据，来源 Markdown 负责检索，跟踪笔记记录研究结论及变化。已有 Vault 优先沿用已确认规则。需要长期维护时，可将本库的入口路径、原件处置方式、属性约定和自动维护范围记在根目录规则文件中。

## 放置和转换

- 初次导入和待入库归档时，将行业研报、行业纪要、跨公司比较和行业催化剂汇总放到对应行业下的「00 行业研究/」，与公司目录同级。首次遇到此类资料时创建目录，已有目录直接复用。公司笔记可链接到相关行业资料。已有「行业研究/」需要改名时，按已确认的迁移范围更新受影响的链接并核对。
- 每个实际归档目录共用一个 `_原件/`。例如 `公告/2026/2026-08-31 半年度报告.md` 的 PDF 放在 `公告/2026/_原件/`，Markdown 优先沿用原件主文件名。不同归档目录各自管理原件。使用可核实的日期或版本区分同名异版。
- 原有 Markdown 直接归档，迁移时校验相对链接及附件。PDF、Word、演示稿等可靠文字默认转成 UTF-8 Markdown，保留正文、标题、可准确提取的表格、单位和统计口径。摘要作为补充。混合版式注明遗漏的图表、不可读的页或提取范围，关键表格回看原件。
- 图片、截图、扫描页及文档内嵌图像默认只归档。用户主动要求时，按指定范围执行 OCR，标出识别不清的位置。可读文字层照常提取。仅图像资料归档后说明如何查阅原件。
- Excel 估值模型保留原始工作簿到 `模型/_原件/`。需要 AI 检索时，在同级目录生成同名 Markdown，记录可核实的版本、关键假设、结果、工作表及单元格。公式、跨表引用及情景计算留在工作簿。
- PDF 来源笔记按实际文件页生成可定位的小标题，如 `### PDF 第 6 页`。关键证据同时链接来源笔记标题和原件，如 `[[仓库内路径/_原件/报告.pdf#page=6|原 PDF 第 6 页]]`。页码从 PDF 文件第一页起算。印刷页码不同时可另注明。Word、PPT、Excel 用可复核的章节、页、幻灯片、表格或单元格，按原件稳定性选择。

## 来源笔记属性

公告、研报和纪要在 Markdown 首行加 YAML Frontmatter。统一键名和类型，只填写能核实且适用的信息。已有 YAML 按键合并，保留人工属性、正文和链接。历史资料按授权范围试补。

| 字段 | 类型与口径 |
|---|---|
| `公司` | 文本列表，使用确认过的公司标准简称。 |
| `资料类型` | 单一文本，统一为 `公告`、`研报` 或 `纪要`。 |
| `日期` | `YYYY-MM-DD`。优先使用已核实的披露日期、报告日期或会议日期。只有原件落款、董事会批准报送日期等时，可用其作为资料日期并在正文注明口径。文件名日期不同则保留两者的含义。只有月、文件修改时间或日不可核实时省略。 |
| `报告期` | 文本列表，如 `2026年半年度`、`2026年三季度`。资料日期与报告期分别填。无适用报告期时省略。 |
| `原件链接` | 文本链接列表，每项带 YAML 引号，如 `"[[仓库内路径/_原件/文件名.ext]]"`。多个原件分别列出。 |
| `药物` | 启用药物目录时按需添加，文本列表。只列来源确实讨论且身份核实的药物。 |

## 双链和检索

历史来源补链与新资料归档涉及药物时，执行[按药物补双链](drug-notes-and-maintenance.md#按药物补双链)。

- AI 在笔记中写入 `[[仓库内路径/笔记名]]` 或带显示文字的链接，Obsidian 展示反向链接。词语共现可用来发现候选，实际落链前核实是同一披露、试验、药物或明确引用。只需有一条有效的正向链接。常用导航可显式互链。
- 优先连接来源、被引用的原件、同一试验的更新、研报点评与公告、研究底稿与成稿。链接放在支撑的段落旁。有同名文件时用仓库内路径。重排目录后核对所有受影响的 Wiki 链接、相对链接和标题锚点。只为有实际阅读用途的专题或目录创建导航。
- 常规 AI 检索先用来源 Markdown、`notes.md`、药物笔记及属性筛选。可配置索引时排除 `_原件/` 和待入库目录，复核时沿链接打开 PDF 或其他原件。来源 Markdown 与原件通过同一出处去重，资料新版本保留独立身份。

## 待入库资料归档与批次核对

「待入库」是暂存入口。「归档」是按主体和资料类型放入正式目录，保存原件，按适用规则生成来源笔记，核对链接与定位，并按已确认方式处置入口文件。涉及已跟踪公司或药物时，在同批完成增量维护。

1. 确认入口、目标、现有同名资料和维护范围。按内容识别重复件，区分同名异版。已经归档的资料复用其原件和来源笔记，并检查是否漏做增量维护。
2. 遇到未建库公司，汇总公司名、待归档文件、拟建路径和放置方式，请用户确认新建范围。收到明确许可后，按已确认的架构为获准公司建目录，同步创建 `key-driver.md`、`notes.md` 和已选用的公司资料入口，再把对应文件归档到该公司。未获许可的资料留在入口，已有公司照常处理。
3. 先准备目标原件和来源 Markdown，检查内容一致、路径和页码正确后，再按已确认的选项保留或移走入口文件。归属不明、版本冲突或转换失败时记录原因，保留入口资料，继续处理其余已明确项。
4. 按[药物与增量维护](drug-notes-and-maintenance.md)更新受影响笔记，跳过已应用的相同条目。验收新增与受影响链接、页码、原件一致性。交付已处理、重复、待处理及失败统计，说明哪些原件已移走。归档结果与逐家公司两份跟踪笔记的内容、更新或拟改文一并交用户确认。
