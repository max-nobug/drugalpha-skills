# Skill 内的 DrugAlpha DCF 生成流程

DCF 引擎在本 Skill 的 `scripts/dcf/`。由平台代码移植，入口是 `scripts/dcf/run_dcf.py`。后续 DCF 改动在此副本完成。运行时需 Python 及该目录的 `requirements.txt` 依赖。公司快照、历史财务及项目假设由当前任务的授权来源提供。

1. 有平台发布数据的本地只读目录时，传 `--company <公司> --source-root <授权数据根目录>`。已有原生公司快照时，传 `--snapshot <快照 JSON>`。两种方式都在 Skill 内构建草稿。
2. 检查纳入药物、适应症及地区。按需求使用原生规则，或用 `--indication-selection`、`--semantic-merges`、`--ai-assumptions` 传入相应平台格式的研究资料。只有明确采用预填建议时才加 `--apply-ai-assumptions`。独立研究使用下方的收入输入入口。
3. 财报默认由宿主代理调用已连接且有权限的金融 MCP。A/H 股按字段覆盖与可用性选择 Alpha 派、iFinD MCP 或其他已授权金融 MCP，按 [财务数据调用](financial-mcp.md) 核对并映射年度合并财报，再用 `--mcp-financials <输入 JSON>` 交给 Skill。按指定来源、市场和字段覆盖选择其他金融 MCP，缺项可回原始披露并逐项标注。旧的 `--history`、`--financial-assumptions` 和 `--prepare-financials` 仍可显式选择。
4. 以原生十年主表、药物及地区分表、里程碑、终值和敏感性为基准。修改输入或样式时，在 Skill 副本的对应阶段调整并重跑。研究假设与依据尽量放在药物测算行旁，来源索引放在原生来源页，主表只展示适用的终值结果。研发、管理费用及终值需要拆解时，按对应假设保留可追溯公式，旧版差额、压力情景和对账明细按任务需要展示。费用口径和净现金来源列在历史财务数据页。DCF 主表和敏感性同步引用净现金及同日总股本，按企业价值加净现金计算股权价值，再除以总股本计算每股价值。
5. 核对药物页至主表的公式、年度、金额单位、终值及模型检查。验收时检查研发与管理费用各扣一次，现金或股本改动后主表、敏感性和情景对比同步更新，当前选定情景与主表勾稽。原生引擎 JSON 与 Excel 应用财务曲线后的估值口径可能不同。以复算后的 Excel 报告估值。存在规则回退或重要范围缺项时，标明试算性质。

```powershell
python scripts/dcf/run_dcf.py --snapshot company-snapshot.json --mcp-financials financial-input.json --out company-dcf.xlsx
```

## 独立 DCF 的默认情景

用户未另指定时，独立 DCF 默认按乐观情景计算，保存 Excel 时将已有情景选择器设为乐观，报告先呈现该结果。采用已有证据支持的乐观参数并列明具体切换项。只有部分资产或参数建立了乐观情景时，明确标注适用范围。若模型提供中性或悲观参数，交付表保留对应的可切换输入。交付前复算并核对当前情景下的销售、归属收入、现金流、终值及股权价值。经营情景名称固定为「乐观」「中性」「悲观」，各公司根据证据分别设定参数。只建了乐观时其余标未测算。Excel「估值敏感性」中的产品收入兑现率档位是相对已选主情景的单因素测试（模板预填 80%／100%／120%，可编辑），与独立经营情景分开。单药获批、授权或多事件同时成功放专项情景，标题写明资产、地区和条件。

公司估值及重跑先读取本次估值跟踪的完整入选药物×地区，再核用户明确要求保留或限定的适应症、治疗线和地区。旧表曾漏算的已入选项目属于原口径，应直接补回。当前平台筛选范围之外的候选资产另列，按用户要求决定是否扩围。只有用户明确指定旧模型范围或仅审阅指定 Excel 时，才沿用该范围并明示差异。

单药患者池按该药的获批标签或有依据的拟开发人群确定。若同公司其他药物覆盖同一突变亚型，该亚型仍留在本药的适用患者池。竞争关系在各药市场份额的证据中体现。同一药物跨线时，按已有治疗路径核对既往已用本药的患者。

## 客户独立 DCF 默认参数

以下为本客户的估值情景参数。按本节覆盖独立估值输入和导出后的相关公式，保留平台原生流程的独立基线。Excel 明示参数、应用范围、计算分母和实际披露来源，并核对这些参数传导到各年现金流及终值。

- **折现参数默认 WACC 10%、永续增长率 2%。** 新建或重算独立 DCF 时，在主表对应输入格预填这两个参数，并核对终值、敏感性和每股价值同步引用。用户明确指定其他值时按当次输入执行。
- 美国月净价为按说明书规格和剂量统一到月的 WAC × 85%。优先取同地区、同治疗线的已上市可比药 WAC，列明价格日期和单位。85% 是固定模型比例，实际净价资料另列。没有调价证据时按当前 WAC 平推，避免在 85% 之外另加未经验证的降价或折让。
- 国内自营产品销售毛利率为 90%，授权销售分成和里程碑收入毛利率均为 96%。公司综合毛利率按各类公司归属收入加权计算。国内供货和其他未指定的收入类别按披露、历史或可追溯的独立假设取值。里程碑仍按触发时点计入当年，永续期只用经常性收入。毛利按收入类型直接套上述规则，截图截断的其他毛利率外推口径不用于本模型。
- 国内逐药、逐适应症及疗线按已核实的实际进度取上市成功率。已获批上市 100%，NDA/BLA 95%，III 期 90%，II 期和已进入 II 期部分的 I/II 期 80%。I/II 期方案目前仍在 I 期剂量爬坡、回填或扩展时，按 I 期处理。I 期、临床前及阶段未确认的已入选项目继续核实代表人群和权益，能建模即单列成功条件 DCF。概率有专项依据时，再给风险调整区间。对用户注明这些概率是乐观估值权重。
- 海外按药物、适应症及授权覆盖地区采用达峰概率。已进入 III 期且已授权 MNC 为 70%，未进入 III 期且已授权 MNC 为 50%，有可核实授权预期的潜在 FIC/BIC 为 50%。区分已实际入组或启动的 III 期与计划启动，核对合作方及合同的地区范围。授权预期及 FIC/BIC 需有可追溯的证据。缺默认档但开发地区、人群和权益方向可核的入选项目，单列海外成功条件 DCF。未签约时，潜在授权只作为明确标注的假设情景。达峰概率有依据时，在归属收入中乘一次。上市前销售为零，上市后直接采用逐年产品渗透率。
- **海外估值先算美国，再按美国销售的 50% 折算欧洲。** 对纳入海外测算的药物，按美国人群、疗线、竞争、费用和疗程逐年测算。欧洲开发进度和当地证据缺口写在说明中，欧洲折算比例固定为 50%。海外主口径为美国加欧洲。药物页分列美国、欧洲及合计的未调整销售与风险/权益调整收入。风险权重只乘一次，归属收入按适用的分成、经济权益及汇率计算，主表引用合计。澳大利亚等额外市场如需研究，单列情景。
- **海外授权单药 DCF 的产品现金流率默认 95%。** 以概率、分成及汇率调整后的公司归属收入为分母。这个参数用于药物页的简化现金流，公司 DCF 按主表的公司费用口径计算。
- 海外授权销售分成率统一按 12% 测算，应用于对应地区净销售额，汇总后乘达峰权重。已签协议披露的版税比例、阶梯和特殊条件单独列示，有实质差异时用合同口径提供对照。12% 是模型参数，不能作为已签条款陈述。海外自营经济权益按自营口径计算。

## 公司费用和永续终值

- 公司 DCF 以最近已核实的合并年报费用金额为基数。销售、研发、管理费用金额在预测前 3 年分别逐年增长 8%、5%、3%，第 4–7 年逐步收敛到成熟期费率 30%、15%、6%，其后沿用成熟期费率。以金额入模，展示费用率时按当期金额和所列收入分母反算。销售费用基数优先使用自营商业收入，集团研发和管理费率使用经常性公司归属收入，明确各分母。销售与管理只有合计披露时按合计建模，费用缺项须标注可复核的回退依据。管理汇总中包含的研发先去重，集团费用在主表只扣一次。收入只覆盖部分管线时，标明范围和费用口径。
- 有盈利历史时，所得税率由历史有效税率起算，最高 15%；亏损公司从 0% 起，5 年内向 15% 收敛。所得税按适用的正应税利润计算，亏损结转有足够披露时独立测算。折旧摊销和资本开支从历史金额起算，逐年增长 3%，占收入比由金额反算。终值所用可持续折旧及资本开支单独核对。
- 营运资本变动优先按可复核的历史营运资本变动 ÷ 收入增量取系数，再乘预测经常性收入增量。历史不可用时，预测第 1–5 年系数取 0%、2%、3%、4%、5%，成熟期 5%。无论是否展示该比例，FCF 公式都须引用营运资本变动金额。
- 主表以永续增长法计算公司终值，基准使用可持续年度自由现金流，乘以 (1+g) 后除以 (WACC−g)，按原模板末年折现因子折回。核查利润率、资本开支、营运资本、经常性收入与再投资，排除一次性里程碑的影响。WACC 须大于 g。末年未进入稳态或现金流为负时，有证据才采用经说明的正常化现金流。客户要求计入终值、末年尚未稳态时，单列可复算的稳态首年现金流情景，逐项给出经常性收入、成熟费用率、税、净资本开支和营运资本的依据，并把其终值现值接入股权价值。明确稳态何时成立及其与末年预测的差异。有限商业期、专利到期侵蚀等明确需要逐年建模时才使用有限期尾期，避免与永续法重复计价。

## 独立DCF药物页的交付格式

[带公式的空白 DCF 模板](../assets/dcf-valuation-template.xlsx)包含十年主表、国内药物、海外药物和里程碑页。使用 `patient_basis` 的独立 DCF 导出直接复制药物页原型，再填实际范围与来源。原平台基线和既有详细患者流输入仍可继续导出。

药物工作表统一命名。只涉及国内时用「药物名」。涉及海外时，国内页用「药物名_国内」，海外页用「药物名_海外」。同一药物拆成不同建模记录时，仍按同一药物判断是否涉及海外。美国、欧洲等市场名称放在页内标题和测算分块。

以已确认的《贝达药业-DrugAlpha-独立DCF-20261112.xlsx》成品为版式和公式链的对照。内置空白模板沿用其十年主表、国内与海外药物页及里程碑结构。各公司重新取证选药及填入假设，贝达实例的资产覆盖或研究结论不作为默认输入。

统一使用用户确认的康诺亚版式。按实际纳入的药物分别建国内及海外页，海外同页按美国、欧洲和合计展示两种收入，同一页内按适应症分块，年份横排，沿用原配色、冻结和列宽。淡粉用于可编辑输入，白底用于公式；对应行「说明」写公式、计算口径、自主假设和取值理由。「来源／依据」只放实际采用的数据库 MCP、公告、文献、数据点和链接。自主测算的产品渗透率在「说明」明确标记【自主假设】。 全工作簿正文统一使用宋体 11 磅，包括各页的项目名、数据字段、数值、说明、来源、口径、脚注、声明、图表文字和单元格批注。说明和批注使用常规字重，表内说明左对齐并自动换行。超链接保留蓝色下划线，深色底上的说明用白字，红底标题和表头使用微软雅黑并保留原有层级。实际采用数据库 MCP 返回的数据时，在「来源／依据」标明实际数据库并链接对应页面。DrugAlpha 的单元格显示「DrugAlpha 创新药数据库」，按[统一来源标注](sources.md#drugalpha-统一来源标注)填写。DrugAlpha 研发进度、适应症获批和催化剂仅链接对应公司的管线页。临床、竞争格局和疾病知识优先链接相应的数据库记录页，缺少记录页时链接对应模块。月治疗费用采用 DrugAlpha MCP 时，注明药名、规格和采用价格，仅链接 DrugAlpha 药物治疗费用测算入口。iFinD MCP 财务数据链接 iFinD 数据库入口。仅采用公开来源的行保留公开出处。项目专属注释填完后再次调用导出器的正文样式函数。核心比例逐项写明分母、地域与人群口径、来源报告值或推导算式。只有间接参照时写明跨队列限制。只有研究判断时写明形成该点值的组成、适用范围和误差来源。

1. **患者池。** 保留发病基数和可治疗患者数。按人群依次计算组织学、分期、突变、进线、检测和支付，按实际适应症处理复发流入与本药跨线去重。目标治疗人群比例由适应症基础人群占比、到达目标疗线比例、检测及治疗可及比例三项相乘。适应症基础人群占比表示基础患者池中符合该适应症年龄、疾病亚型、分期、严重程度等条件的人群比例。已单列的标志物、目标疗线、检测和治疗可及性在相应项计算。 「说明」先显示三项相乘的公式，下一行显示按公式顺序代入的百分比与结果。说明值从同一行参数单元格动态读取，改参数时联动更新。补充假设另起一行。三项直接取证或估计并做成可编辑输入；队列证据及口径放在来源列，避免从更多细项先算出汇总比例。标志物比例单列。上游使用同一分母的条件比例，不重复折减。
2. **产品销售。** 保留上市年、渗透率、药物份额、使用人数、治疗时长、月治疗费用、产品终端销售。上市前渗透率为零，上市后按竞争和准入判断直接输入逐年渗透率。取消单独的上市后采用进度系数。关键假设及来源放在对应行右侧。
3. **归属收入。** 在药物页底部汇总终端销售，再按适应症对应的国内上市成功概率或海外达峰概率、权益和汇率计算归属收入。已在模板中按共同权益结算的资产保留原有汇总逻辑。有供货时和授权分成分行。DCF 主表直接引用归属收入合计，独立峰值及目标金额分析另交付。

十年主表保留原来的预测列、公式、配色和引用。按估值跟踪的独立入选清单，每个药物×地区都在「DCF估值」主表占一行。逐年展示计入主情景的归属收入。仅有成功条件测算的组合，在原行注明「成功条件」，逐年链接未作概率加权的归属收入，说明风险调整后贡献待定。公司总收入公式排除这些行，成功条件下的单药DCF在主表右侧单列。该简化单药DCF按药物页现金流率计算，须注明假设及局限。暂无法量化的入选项保留主表行、说明缺口，收入留空。部分适应症已量化时只汇总该部分，并标明剩余范围。药物页保留原有单位，并核对人数、费用和销售额单位换算。交付前展开患者流，修改一个上游参数，核对可治疗患者数、产品销售、归属收入和 DCF 主表均联动；仅改布局时逐项对账原有公式和估值。

## 独立药物收入

取证前按[药物销售及 DCF 参数的第一数据源](competition-peak-mcp.md#药物销售及-dcf-参数的第一数据源)逐项执行。患者规模、Biomarker 比例、药费、肿瘤疗程、适应症进展和渗透率依据均以实际 DrugAlpha MCP 返回为先。只有该参数缺少可用结果时才定向联网补证。在药物页「来源／依据」逐项标明实际证据，在「说明」写推导和假设；按[逐项验收](financial-acceptance.md)核对其已进入公式或假设。公司财务仍按[金融数据路由](financial-mcp.md)取数。

正式公司独立估值使用本包 `run_dcf.py --output-dir` 导出。按平台的纳入规则导出药物、适应症、地区和预测年，再填写逐年输入。两次运行使用同一数据和适应症选择配置。

### MCP 直接入口

1. 调 `get_company_valuation` 并读完所有分页。把原始结构化响应保存为 `valuation-mcp.json`，多页按顺序存为 JSON 数组。脚本只读取身份和范围布尔条件，峰值、分成和概率金额不进入独立测算。
2. 查管线、催化剂和临床证据，独立确定各药物×地区的适应症。把清单存为 JSON 数组，例如 `[{"drug_name":"药物正式名或返回中的别名","market":"china","indication":"目标适应症、线数及亚型","phase":"实际阶段","source":"证据及适用理由"}]`。海外填 `us`，欧洲由生成器折算。一个药物可按地区和适应症填写多条。此清单用于确认适应症，入选药物×地区范围由 MCP 返回自动锁定。
3. 用第一条命令导出 `revenue-inputs.json`，保留其 `valuation_scope` 作为报告验收的范围清单。只填各 `markets` 的独立输入。带相同 MCP 响应和适应症清单调用第二条命令生成正式 Excel。

```powershell
python scripts/dcf/run_dcf.py --valuation-mcp valuation-mcp.json --research-indications indications.json --revenue-scope-out revenue-inputs.json
python scripts/dcf/run_dcf.py --valuation-mcp valuation-mcp.json --research-indications indications.json --revenue-inputs revenue-inputs.json --mcp-financials financial-input.json --output-dir outputs --report-date YYYY-MM-DD
```

### 已有原生快照

```powershell
python scripts/dcf/run_dcf.py --snapshot company-snapshot.json --revenue-scope-out revenue-inputs.json
python scripts/dcf/run_dcf.py --snapshot company-snapshot.json --revenue-inputs revenue-inputs.json --mcp-financials financial-input.json --output-dir outputs --report-date YYYY-MM-DD
```

- 新独立 DCF 在每个 `markets` 条目填写 `patient_basis`。`patient_population` 按预测年填人数（人），`biomarker_ratio`、`clinical_fit_ratio`、`target_line_ratio` 和 `access_ratio` 分别填 0–1 的可编辑比例。后三项在药物页同一行直接相乘，再与患者规模和标志物比例相乘。在 `assumptions` 填计算口径、假设及取值理由，在 `sources` 填实际采用的来源。引擎从这五项算 `eligible_patients`，如同时提供该年度序列则逐年校验。
- 逐年直接填 `product_penetration`，分母是可治疗患者，范围 0–1，同时将 `values.class_penetration` 和 `values.product_class_share` 留空。也可提供同类渗透率和本品份额作为有证据的两项输入，引擎相乘后在表内展示逐年产品渗透率。疗程 `treatment_months` 和当地币月净价 `monthly_net_price` 仍在 `values` 逐年提供。
- 正式独立 DCF 的 `patient_basis` 海外条目由生成器统一设置 `europe_ratio=0.5`。旧输入中的 0 或其他比例在按新模板重跑时会自动统一。假设列注明用户估值规则，另有子公司权益时填 `economic_ownership` 和出处，与分成分开。历史输入可沿用原 `eligible_patients` 和 `patient_funnel` 复现旧布局；同一药物地区页统一使用一种患者流输入口径。
- `launch_year`、`success_probability`、`economic_share` 分别核对。独立估值的成功概率字段国内填上市成功率，海外填达峰概率，按上方客户默认参数赋值。海外再填人民币兑当地货币的折算系数 `exchange_rate`（1 单位当地货币折合人民币）。用户指定全成功情景时可填 1 并标明。按[峰值测算手册](peak-workflow.md)独立判断患者、渗透率、份额、疗程与可比价格，美国净价按本节规则折算。每个字段可同时提供 `assumptions` 与 `sources`，至少一处给出解释或证据。来源可写名称和真实 URL，缺少可靠来源时留空或明确 MCP 取证缺口。`penetration_basis` 默认 `assumption`。只有整组渗透率来自同口径观测且注明可核来源时可填 `observed`。旧版混写输入仍可导出，保留原文字及可识别链接。
- 平台峰值只用于判断是否为正以确定原生范围。独立入口禁用峰值分配、渗透率反算、首年销售反算和峰值收入回退。月费用和疗程分别取证。上市前收入为零。原生公式按当年新使用本产品患者乘完整疗程估收入，治疗跨年明显影响年度归属时，另做队列校核。
- 逐年输入和对应依据在同一药物页并排展示。检查份额调整是否传导到产品销售、归属收入和 DCF 主表。输入模板中的 valuation_scope 由平台筛选自动保留，最终以源快照为准。适应症能建模但成功概率待定时，将 values.success_probability 填 null，并在同名假设或来源字段说明依据缺口，标准 patient_basis 药物页会生成成功条件单药 DCF。满足手册停止条件才给已分配的适应症行填写 status=unquantified 和 reason。遗漏必填市场行、越界输入会中止导出；源快照入选但尚未形成可测适应症的市场仍自动保留主表行。源快照入选但草稿没有市场条目时，须先补适应症、开发地区及权益证据。确实无法量化时，在收入输入顶层的 unmodeled_market_reasons 数组按 product_id、market 和 reason 记录已查证据、具体缺口及恢复条件；保留该主表行，泛化待核占位过不了正式交付。核对原生范围和实际研究范围，尤其是海外市场覆盖。当前副本的原生市场键为中国和美国，美国子集须按实际覆盖标注。
- 正式独立 DCF 用 `--output-dir` 生成 `XXXXDCF估值模型-YYYYMMDD-DrugAlpha Skill生成.xlsx`。日期与本次报告日期一致。`--out` 仍支持基线及旧流程。若另做市场隐含预期分析，在独立 DCF 完成后报告并单独标明隐含情景。
