# 催化剂研究员：DrugAlpha MCP调用指引

与[独立执行手册](catalyst-workflow.md)配合。以下为配置时当前连接的公开能力；每次任务先看实时工具说明，若版本改变以实时契约为准。工具可能带 `mcp__drugalpha__` 或 `mcp__codex_apps__drugalpha_` 前缀，使用当前可用的一套，不对等价连接重复查询。配置文档不是权限授权，也不保证数据完整。

## 1. 路由

先执行[全能力路由及完成检查](data-access.md)，主动选取本题相关入口；查询成功与工具可见分别记录，已共享的合格返回不重复获取。

| 问题 | 工具与用途 |
|---|---|
| 公司/药物身份 | `resolve_entities`：仅公司和药物，本次结果用于后续主体 |
| 未来事件、时间未知事件 | `get_catalysts`：正式已发布催化剂及证据，主入口 |
| 核当前阶段、适应症/线数/单联用 | `get_pipeline`：校验事件依赖，不把管线历史文字全当未来事件 |
| 已发生公告、BD或监管事件点评 | `get_company_research_inputs`：先取对应原始公告，平台近期覆盖不足则联网官方补全文 |
| 竞品事件是否改变地位 | `get_competitive_landscape`：筛真正相关候选，再用本次解析的具体资产查同窗口事件（含未知时间），联网核最新版指引；不全库遍历 |
| 新数据临床意义 | 交临床成员，必要时按[临床调用指引](clinical-mcp.md)取 `get_clinical_evidence`，不能用催化剂标题代替临床结果 |

没有独立会议日历、BD交易全文或所有国家监管目标日的查询工具，不虚构此类接口。当前已开放 `get_morning_brief`：涉及最新海外事件、海外同类或异动时，主动用于发现线索，再回官方披露核实。默认最新已发布未必今日；date是北京时间晨报日期。完整晨报须分别查询company_events与market_moves并各自分页；单项事件仅查相关section即可。没有公司/关键词/任意时段筛选，不把它当通用新闻库或因果证明；当前竞争映射尚未接入。公告及下载分别遵循实际已注册工具，不沿用旧的“未开放”判断。联网补充见[catalyst-evidence.md](catalyst-evidence.md)。

## 2. 先解析主体

`resolve_entities` 示例（参数，不含工具前缀）：

```json
{"query":"信达生物","types":["company"],"limit":5}
```

```json
{"query":"IBI363","types":["drug"],"limit":5}
```

仅用本次唯一匹配的 `entity.type/key`；歧义确认，截断先缩小名称，不选第一条凑结果。药物别名及多个合作公司不等于多个独立分子；公司及药物关联按当前证据保存，不猜授权范围。示例中的主体名称不构成实际研究结论。

## 3. 取催化剂并覆盖未知时间

单对象示例；`<...>`是需要替换的占位符，不能原样调用：

```json
{
  "subject":{"type":"company","key":"<本次解析的公司key>"},
  "includeUnknownTime":true,
  "page":{"limit":10}
}
```

省略日期默认未来180天。明确窗口时加入 `dateFrom`、`dateTo`（YYYY-MM-DD，按当前日期和用户范围生成，不复制旧日期），单次最多366天；分页沿用同一窗口。对过去已过期的重要指引单独核官方事实，不把未来窗口零返回当成历史事件不存在。

批量示例（最多10个已解析主体；与 `subject` 二选一）：

```json
{
  "subjects":[
    {"type":"company","key":"<本次公司key>"},
    {"type":"drug","key":"<本次药物key>"}
  ],
  "includeUnknownTime":true,
  "page":{"limit":10}
}
```

通常先不设 `eventTypes`，避免漏负面或命名不同的事件；需要限定时使用已发布类型名称片段，例如 `["临床"]`，不猜枚举代码。多类型取并集，与日期条件取交集。会议/BD没有返回不意味着不存在，去公开一手资料补查。

分页沿用全部主体、日期和类型筛选，`page.cursor`只填本次 `nextCursor`：

```json
{
  "subject":{"type":"company","key":"<与首轮相同的公司key>"},
  "includeUnknownTime":true,
  "page":{"limit":10,"cursor":"<本次上一页nextCursor>"}
}
```

首轮若显式设日期/类型，后页也须原样带上；示例省略不代表可丢筛选。查所需完整窗口时继续分页；受限停止须注明仅部分，不能写全量。`coverage.complete_within_scope`描述授权发布集，不证明本次已翻完全部页面或已覆盖平台外全部事件。

## 4. 返回结果怎样用于研究

- 逐个读 `subjectResults`：某主体的 `matchedEvents` 是全窗口事件数，不是本页数；同一事件关联公司和药物时去重返回，主体计数之和可能大于独立事件数。零匹配、未覆盖和部分覆盖分别保留。
- `time.originalText/precision/startDate/endDate`一起保存。区间与查询窗相交不代表事件必在截至日之后；不得裁剪成更精确的日期。未知时间纳入后单列，不断言在窗口内。若见 `UNKNOWN_TIME_EXCLUDED`，明确仍有未纳入的未知时间事件，按实时契约补取或披露。
- `informationNature`及 `timeNote`用于内部核判断，最终以“公司预计”“按周期推算”等自然语言说明，不输出技术标签/字段列。预计不等于承诺，快照发布日不等于原始披露日。
- `indication`保留该事件原文；`drugLinks.targetSummary`是已确认关联药物的靶点背景，不是临床结果，也不是整条联合事件共同靶点。缺失用“来源未提供”，不填“无”或0，不把适应症文字当标签批准证据。
- 每条 `evidence`独立保留标题、日期、类型、完整URL与定位。无URL就说明来源未提供链接，不借用其他事件链接，不猜URL。联网独立取得原文可另列来源，不能伪装成平台本来返回了链接。
- `dataAsOf/publishedAt/sourceVersions`留审计底稿，旧版本与最新披露冲突时分开保存并说明。关键事件优先追原文，不只复述平台摘要。

## 5. 公告与当前状态交叉验证

公司已发生事件点评使用本入口，示例主题由用户已给事件替换：

```json
{
  "query":"<公司名称>",
  "sections":["announcement"],
  "eventSummary":"<用户提供的BD或监管等主题关键词/公告标题>",
  "includeAnnouncementText":true
}
```

该工具支持名称直接查询，无需先遍历目录；歧义按返回候选处理。核标题、主体、发布时间、`body.text`、`textStatus`与 `truncated`；正文未取得不称已读公告。近期关键词匹配不保证全部历史公告，纯前瞻梳理不编造用户事件主题去调用默认财报。用户只说“最新公告”又没有主题，依实时工具要求澄清。

阶段核对示例：

```json
{
  "subject":{"type":"drug","key":"<本次药物key>"},
  "page":{"limit":10}
}
```

对应 `get_pipeline`，按需加入当前支持的原文关键词过滤并保持分页。精确人群检索零结果先判断是否字段过窄，不将零结果作为无竞争或无研究结论。靶点竞争示例：

```json
{"query":"KRAS G12D","queryType":"target","view":"assets","page":{"limit":10}}
```

靶点不走实体解析；同适应症另用 `queryType:"indication"`和具体患者条件。资产数、公司展示项、试验行和事件数分别处理。候选→当次解析→催化剂查询，不从旧文件抄key。对关键上市说明书、注册状态、条款或完整临床正文仍须官方原文，不能仅靠管线阶段。

## 6. 失败、权限与底稿

不读业务数据库/后台草稿绕过当前账号；不嵌凭据、不承诺其他用户免授权。鉴权或订阅失败按返回动作说明；可公开核验部分继续联网，不能声称MCP查询成功。限流遵守重试提示；无效参数先对实时契约修正。空结果检查实体、窗口、类型、未知时间及分页后，最多改写一至两次；连续两轮无新增停止，报告覆盖缺口。

内部保留实际调用参数（不含凭据）、本次解析、分页/覆盖、原文来源、事件去重与冲突。用户正文呈现事实、事件与投资判断，必要时文末一句说明缺口，不展示内部ID/游标或日志。仅查询和生成研究产物，不导入/发布催化剂雷达，不自动安排持续监控。
