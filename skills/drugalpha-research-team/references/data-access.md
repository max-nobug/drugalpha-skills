# DrugAlpha 数据能力与研究员路由

2026-10-28按当前工具注册及实时契约核对：47个注册入口、去重后24类能力。此为能力盘点，不表示24类数据、订阅或下载权限均实测成功。每次以实时工具说明和实际返回为准。

## 1. 研究前置检查

综合决策模块及承担单项研究的成员均须先读本表中与问题相关的行。按以下顺序识别并验证 DrugAlpha MCP。

1. 从当前会话的可用工具中查找名称任意位置含 `drugalpha`（不区分大小写）的候选，结合服务归属确认。兼容不同客户端的命名，示例前缀只用于说明。
2. 名称无法判断时，查看工具描述中的 DrugAlpha 标识、服务归属及实时参数，确认是否覆盖本题所需能力。等价入口择一。
3. 使用本题实际需要的只读查询验证连接和模块权限，例如用目标靶点或适应症查询竞争格局。核对实际返回、条件解析及覆盖。连接显示可用只能作为发现线索。同一次研究已有同口径的有效返回时直接复用。

| 查询状态 | 处理 |
|---|---|
| 查询成功且有可用数据 | 核对人群、地区、时间、来源及必要分页。将实际匹配的数据用于判断。 |
| 查询成功但无匹配或仅部分覆盖 | 检查条件解析并按对应手册补查。保留原比较口径，对剩余缺口按允许范围联网补证。 |
| 当前会话未发现 DrugAlpha 连接 | 记录当前会话未发现连接，按[接入选择与验证](#接入选择与验证)询问用户。 |
| 已发现连接，但缺少本题所需工具 | 说明当前会话缺少的具体模块。 |
| 已连接但鉴权或模块权限受限 | 说明受限模块和所需授权，沿用已获授权的资料。 |
| 超时或服务异常 | 根据返回提示缩小查询或有限重试，仍失败时记录异常类型。 |
| 参数错误 | 核实时参数和条件解析后修正查询，保留实际状态。 |

用户已允许联网补证时，直接按授权范围用公开一手资料补缺。按[统一来源标注](sources.md#drugalpha-统一来源标注)把实际采用的 DrugAlpha 数据、公开证据及链接对应到具体表格或事实。交代未由 DrugAlpha 核验的范围和原因。用户限定仅用 DrugAlpha 时，保留证据缺口。

研究员独立选择入口，不等待用户指明接口。下表“触发”一旦适用，必须查询或复用本次已有的、同条件且足够新的实际返回；权限受限、覆盖不足或不适用时，记录具体原因。公开补证按上述授权范围执行。不是每次把24类全部调用，也不因本表增加固定研究员。

内部建立简短数据任务单：**研究问题→所需数据→责任人→实际取得/复用/受限状态→影响哪项判断→待补缺口**。综合决策模块派发时给原始问题及相关入口，不能只给泛泛角色定位。单成员任务由该成员兼做这项检查，无需为了查某个工具再启动其他成员。

同一条件由一个成员负责获取并共享，保留实际返回、截至时间、原始来源、分页及覆盖。跨任务旧资料须检查时效和身份；不复用旧ID猜本次对象。报告仅呈现研究证据及必要边界，不堆工具日志。

### 接入选择与验证

首次调用本 Skill 时，当前 Agent 检查连接及可按需加载的工具。已连接且本题工具可用时直接查询。只有完成工具发现后仍找不到连接，才由当前 Agent 向用户询问一次。权限受限、超时、所需模块缺失或无匹配时，按上表处理。已有选择直接沿用，各研究员共用检查结果。

> 当前会话没有发现 DrugAlpha 创新药数据库 MCP。如果你还没有 DrugAlpha 创新药数据库账号，请先到 [DrugAlpha 创新药数据库官网](https://drugalpha.com/) 注册自己的账号。你希望我帮你配置，还是你自己配置？

用户已有账号时省略注册链接。出现鉴权或模块权限问题时，提示用户检查现有账号的登录、授权或订阅状态。

- **AI 帮忙配置**。识别当前客户端，查阅 [DrugAlpha 官方 GitHub](https://github.com/max-nobug/drugalpha-mcp) 的 README.md 和 INSTALL-AGENT.md。按[连接说明](../README.md#2-连接-drugalpha-创新药数据库-mcp)协助添加官方连接器或 Streamable HTTP 服务。客户端需要用户操作时，告知具体入口和待完成步骤。
- **自己配置**。给出当前客户端的具体菜单路径、服务名称和地址 `https://drugalpha.com/mcp`、传输方式及客户端支持的 OAuth 或个人 Key 填写方式，并附 [DrugAlpha 官方 GitHub](https://github.com/max-nobug/drugalpha-mcp)。当前客户端无法确定时，只询问客户端名称，再给对应步骤。用户选择个人 Key 时，按[前置检查中的个人 Key 连接步骤](../SKILL.md#六种模式共同取证优先调用-drugalpha-创新药数据库-mcp)提供官网创建路径与客户端填写项。
- **配置后验证**。注册、浏览器授权和个人 Key 的创建及填写由用户在对应页面完成。刷新工具列表，必要时请用户新开会话，再执行本题的实际只读查询。单独验证连接时可查询恒瑞医药的公司身份。根据实际结果分别说明连接是否验证通过、本题模块是否可用。

用户暂缓接入时，按上文已允许的资料范围继续研究，并标注 DrugAlpha 核验缺口。

## 3. 问题驱动的最小执行路径

- **药物临床价值**：临床证据＋匹配指南标准治疗；候选不全则补适应症竞争，核关键亚组/核心终点，缺项去论文、注册、会议原图和官方披露。竞争表不能替代疗效取证。
- **商业化/竞争/市场空间**：适应症竞争底稿→同靶点补充→当前具体适应症管线→流行病学正文→相关同类实际销售；独立DCF任务仅用估值跟踪确定范围，不采用峰值金额或据此校准参数。既有同条件合格返回直接复用。药价/费用仅按需要查。须给目标患者及有输入/公式/单位的市场或销售区间，资料不足则明确缺失参数与条件式测算，不能只列“市场大”。
- **未来催化剂**：催化剂含未知窗口→管线依赖及原始事件状态→真正相关竞品；涉及海外最新事件补晨报，再回官方原文核日期/增量。不为国内单药强行读取整份海外晨报。
独立财务估值按[财务手册](financial-workflow.md)及[DCF规范](valuation-dcf-workbook.md)执行：估值跟踪用于圈定独立范围及列示平台参考结果，独立参数单独取证、患者流正向推导。按[报告模板](valuation-report-template.md)交付同版 Markdown、Word 和可复算 DCF Excel。
- **覆盖池/平台观点/行业研究**：综合决策模块按问题取概览、精选、板块资料，再决定深入哪些公司。单数据问题不扩成全团队。

## 4. 完成检查与退回

1. 是否漏了本题相关且当前注册的入口？漏用必须先补或说明具体不适用原因，不能让用户再教调用。综合决策模块在派发、回收及整合时检查。
2. 是否真的读正文及足够分页？临床/指南sources、竞争assets与所需sources分别分页；流行病学和指标定义各用自己的目录→正文。覆盖不全必须限定排名和结论，不称全量。
3. 是否把返回用于结论？商业化须列真正同人群竞品及进入市场时位置，给患者和空间；临床须让标准治疗及关键亚组改变定位；财务须检验原峰值/资金；催化剂须剔除已发生或无新增信息事件。仅写“已调用”不算完成。
4. 是否区分已发布事实、平台预测/个人模型、外部原始资料和自主假设？零匹配、未覆盖、权限失败、工具未注册、正文不可读、尚未查询分别记，不能一律称数据库没有数据。
5. 只有当前任务实际成功返回的模块才能说已验证可调用。对权限或公开覆盖缺口主动说明并补一手公开资料；连续两轮无新增停止同缺口扩搜。不读后台/业务库，不绕权限，不写回估值或发布。
