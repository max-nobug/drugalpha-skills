# 临床研究员：DrugAlpha MCP调用指引

先按[全能力路由](data-access.md)选择本题相关入口并执行完成检查。临床价值评价必须获取/复用匹配临床证据及指南标准治疗；候选不全时主动取适应症竞争底稿，缺终点、关键亚组或标准治疗数据时联网补齐。目录、标题或一次成功调用不能代替读正文及比较结论；已由其他成员核验的同条件资料共享复用。

参数依据2026-10-14本会话可用工具说明整理。工具可能更新，每次执行仍以当前schema、权限和返回警告为准。本文件给调用模板，不代表已经执行临床数据查询。

## 1. 入口选择

当前服务可能显示为 `mcp__drugalpha__`，也可能为 `mcp__codex_apps__drugalpha_` 前缀。按当前实际注册的工具名调用；两者同名能力不要重复查。不硬编码连接名、账号或凭据，不通过读取本地业务库绕过权限。

先读取 `drugalpha-research` 技能及查询指引（若当前可用），再核以下相关工具，不要求每项任务全部调用。

| 信息需求 | 入口 | 输入与关键规则 |
|---|---|---|
| 公司/药物身份 | `resolve_entities` | `query`名称或代号；`types`为company/drug数组；只能解析公司/药物，不解析疾病或靶点 |
| 公司临床事件原文 | `get_company_research_inputs` | 公司`query`或本次确认的`companyId`；事件点评选announcement、传主题并读正文 |
| 研究登记号/阶段/靶点背景 | `get_pipeline` | 先解析公司/药物；`subject`仅type与key；不把管线行当独立药物或疗效证据 |
| 临床指标与结构原文 | `get_clinical_evidence` | 已知药物且支持药物模式时用 `queryType=drug`，`query` 填药名，可用 `indication` 限定患者条件。也可用 `queryType=indication` 按适应症查 |
| 治疗路径/推荐 | `get_guidelines` | 按单一病种查，再筛对应线数。独立查询指南 |
| 疾病背景人数与分层 | `get_epidemiology` | 先无areaKey/groupKey读本工具目录，再用本次目录标识读正文 |
| 指标含义 | `get_metric_definitions` | 先读本工具自己的目录，再按其返回的页面标识读取；不复用流行病学目录来假定覆盖 |
| 说明书字段 | `get_drug_instructions` | 先query选候选，再sourceId读所选来源原文；二选一，不冒称完整官方标签认证 |
| 临床比较对象线索 | `get_competitive_landscape` | 仅综合任务需要且未由商业化共享时查；默认适应症assets，研究来源可用sources；它不返回临床疗效 |

### 按药物查询临床数据

已知比较药物且当前工具参数支持 `queryType=drug` 时，`query` 直接填通用名或研发代号，无需先解析实体。患者条件明确时，将疾病、线数、标志物等条件原文填入 `indication`。需要先盘点该药有哪些研究时，可省略 `indication`，再按目标适应症筛选或带条件重查。遇到同名候选先核身份，再用已确认的名称或工具支持的标准标识查询。分页保持 `queryType`、`query`、`indication`、`view` 与页大小一致。

```json
{
  "queryType": "drug",
  "query": "IBI343",
  "indication": "CLDN18.2阳性晚期胃癌三线及以上",
  "view": "sources",
  "page": {"limit": 20}
}
```

以上为支持药物模式的连接示例。旧版连接仅支持适应症模式，或实际调用拒绝药物模式参数时，改按适应症查，再按药名、别名和试验号筛选。必要时查管线确认身份和研究阶段。两种模式都须核对返回研究的实际人群、阶段和分析集。不要传工具未声明的字段。

目标药物有记录并不表示比较数据已齐全。按[临床数据比较与PubMed补证流程](clinical-methods-comparison.md)建立比较对象清单，逐药核关键研究、最新随访和疗效/安全性字段；缺项必须主动到PubMed及会议、监管等一手来源补证，不等待用户提供竞品论文。适应症竞争格局可作候选线索，不能替代竞品临床结果。用户明确限定只用数据库时保留该限制及比较缺口。

## 2. 适应症查询及分页

示例仅演示参数形式；真实任务必须替换为用户或综合决策模块已确认的患者条件，不能直接套用示例疾病。

```json
{
  "query": "EGFR突变肺癌一线",
  "queryType": "indication",
  "view": "sources",
  "page": {"limit": 20}
}
```

以上分别适用于 `get_clinical_evidence` 或 `get_guidelines`，按本次问题选择。不得将“肺癌”自行改为NSCLC，删除“一线”，或新增用户未确认的突变亚型；`assets`不能用于这两个工具。

收到结果后按顺序检查：

1. 返回是否为错误；不能把失败当零条。
2. `data.query.ready`及`unresolved`：若 false，先看是否提示多个疾病或多个线数。已知的并列分支分别查询，保留原人群条件。只有含义仍不明确时，将未解析项交综合决策模块确认。
3. 解析范围、标志物状态/亚型/阈值配对、分支条件、额外条件、匹配解释和条件覆盖，是否支持本次问题。来源未保存条件不等于无该限制。
4. `data.items`：仅提取相关研究；`content.metrics[].structuredText`保留治疗臂和亚组结构，`value`和`unit`保留原值。不把PFS/OS等同名指标直接拼成可比结果。
5. 每项来源名称、链接、版本、披露日、数据截点和阅读范围。顶层发布时间/查询日不能作为研究数据日期。
6. `pagination.hasMore`：有下一页时使用本次`nextCursor`，其余query、queryType、view、limit不变；读完或明确只获得部分。

下一页模板（尖括号必须替换，不能原样调用）：

```json
{
  "query": "本次已确认的原始患者条件",
  "queryType": "indication",
  "view": "sources",
  "page": {"limit": 20, "cursor": "<本次返回的nextCursor>"}
}
```

没有下一页仅表示本次授权发布范围读取完毕；`complete_within_scope`不表示全世界研究收集完整。`no_matches`或`not_covered`不能写成没有药物、没有临床证据或没有指南。

### 精确查询未命中时的补查

1. 已知药物时按上文选药物模式或适应症模式。药名加宽泛后线只返回早期研究或缺目标三期时，逐药用准确病种、已确认的标志物及试验实际线数回查三期。先用药物模式加精确 `indication`，如仍缺项，按同一精确条件改用适应症模式并按药名和试验号筛选。不同药物的三期线数不同时分别查询，例如三线及以上和二线及以上。核对试验阶段与登记号后，再联网补余下缺口。
2. 精确临床查询未命中或缺关键研究时，先把已知的并列病种与线数拆开。后线任务对每个病种另查一次“病种 + 原分子标志物及状态 + 晚期后线”等对应表述，再逐条核对药物、实际入组线数和试验阶段。宽查仅用于发现证据，报告的目标人群保持原口径。早期或未明确线数的记录只作对应阶段的背景，不能替代同线三期数据。
3. 指南先按病种分别查，用返回的原适应症和方案条件筛选目标线数及包含该线的推荐，保留版本、适用人群和来源。目标药物是否纳入指南与同线标准治疗分别核对。
4. 成稿注明实际使用的 DrugAlpha 临床记录和指南方案，以及联网补齐的研究或终点。精确查询无结果时，先完成上述补查，再判断平台覆盖缺口。关键三期或亚组仍缺时，定向查会议原始材料、论文及附录、监管文件或公司原始披露。

## 3. 公司与药物管线查询

先按真实名称解析，例：

```json
{"query": "首药控股", "types": ["company"], "limit": 10}
```

使用本次返回的唯一确认实体。多个候选须确认，被截断不能视为唯一。再调用 `get_pipeline`：

```json
{
  "subject": {"type": "company", "key": "<本次确认的entity.key>"},
  "page": {"limit": 20}
}
```

药物用同样流程，解析types为drug，subject.type为drug。subject不能传名称字符串、JSON字符串或带label的完整实体。不复用历史示例key。

默认不加阶段/适应症筛选。确需筛选时，`phaseKeywords`、`indicationKeywords`分别最多5个来源原文关键词；同组并集、两组交集，不做同义词扩展。缺字段会被筛选排除，保留警告。已由商业化成员取得的本次管线直接复用。

核原始阶段、研究登记号、适应症、药物身份、靶点来源与进展文字。上市或历史记录可能仍在表中，不能把所有条目写为当前在研；快照发布日期和跟踪列不等于每项进展发生日。药物机制细节或疗效缺失时联网补证，不能由靶点字段推导结果。

## 4. 公告/临床事件入口

事件点评先读 `get_company_research_inputs`。参数示例：

```json
{
  "query": "<本次研究公司名称>",
  "sections": ["announcement"],
  "eventSummary": "<用户给出的临床事件主题关键词或公告标题>",
  "includeAnnouncementText": true
}
```

公司query、companyId或旧companyKey三选一；有歧义时确认本次候选，再按当前schema使用companyId。仅要临床原文无需顺带请求financial_consensus。只有金融一致预期不能声称已读公告。

核所选公告主体、标题、日期、主题匹配、正文body/textStatus、页数和truncated。原入口为近期窗口关键词检索，不保证全公司历史或最新全部公告。未指定“最新公告”的主题时请综合决策模块确认，不以默认财报代替。扫描解析失败或截断时按公开原公告补正文；无法取得则说明实际阅读范围。

## 5. 知识页目录与说明书

`get_epidemiology`与`get_metric_definitions`分别先执行目录查询：

```json
{"page": {"limit": 20}}
```

完成该目录分页，再选本次标题/概述匹配的页：

```json
{"areaKey": "<该工具本次目录返回值>", "groupKey": "<该工具本次目录返回值>"}
```

两个工具的目录覆盖不同，分别取证，不猜标识。多页可能匹配时确认；目录不是数据正文，也不是患者条件匹配结果。肺癌总体发病数据不能改称NSCLC或某突变人数；不乘比例自动估人群。指标定义不代替具体研究方案，不跨疾病合并同名定义。

`get_drug_instructions`先 `{"query":"<真实药名>"}`，核候选药名/品牌/来源，再 `{"sourceId":"<本次选定候选id>"}`；query与sourceId二选一。说明书沿用现有公开药学来源，可能为首个可用品牌，不代表所有厂家或最新正式批准标签；读到栏目原文再提取，缺失不由AI补齐。最终标签判断必要时回到监管/上市许可持有人正式版本。

## 6. 空结果、失败与联网衔接

| 情形 | 执行动作 |
|---|---|
| 无匹配/覆盖不足 | 检查名称、条件解析和阅读范围；按本节前的补查流程拆分和筛选，保留原比较口径。仍有关键缺口再转公开一手来源 |
| 条件未解析/对象歧义 | 将未解析项/候选交综合决策模块确认；继续不依赖它的工作 |
| 工具未注册 | 刷新发现可用能力；仍无则说明本次无法调用，用允许的公开来源，不凭目录或记忆造接口 |
| 权限/订阅/登录错误 | 遵循错误action由用户处理需要的授权，不索取凭据，不循环重试或换连接绕过；公开补证另标来源 |
| 限流/配额 | 按retryAfterSeconds和允许的工具重试规则等待或停止；不并发刷接口或切账号规避 |
| 参数错误 | 读当前schema、修正后重试；示例参数不能优先于实时schema |
| 游标失效 | 按错误action重新开始原查询；记录新旧版本及去重，不能混用游标冒称已读完整 |
| 预算截断/正文不全 | 按工具允许方式缩小相关来源/页大小或读原文，保留患者条件；不能声称全量/全文 |
| 原文或数值冲突 | 分别保留平台与一手新披露的来源/截点，经临床核验后修正研究判断；不修改数据库 |

重试依据当前工具的retryable/action；同一缺口连续两轮无有效新增即停止扩展。额外联网流程和证据提取标准见[临床执行手册](clinical-workflow.md)。
