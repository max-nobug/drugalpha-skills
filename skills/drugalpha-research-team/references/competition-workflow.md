# DrugAlpha竞争格局分析：独立工作流

## 服务场景

- **投资研究**：识别研发领先者、直接替代方案及未来竞争变化。
- **BD 决策**：筛选可差异化切入的资产和适应症，核同赛道授权、地区权益与合作方布局。
- **医学事务竞品分析**：按同适应症、治疗线及人群整理对标产品、开发进度和证据缺口。
- **医保谈判证据准备**：核拟准入人群当前实际可用的治疗及支付覆盖，记录可作为比较基准的方案和适用理由。

用于判断特定资产在同靶点及同适应症中的研发位次、真实替代关系和进入市场时的竞争。独立完成必要取证，不要求安装其他DrugAlpha Skill，不等待其他研究员交接。详细接口规则见[DrugAlpha调用指引](competition-peak-mcp.md)，公开来源路径见[联网补证](competition-peak-evidence.md)，共同口径见[证据规则](evidence.md)。

客户材料接入按[客户资料与能力检查](sources.md)执行，研究偏好读取[客户配置](preferences.md)。客户可以调整关注指标和输出详略；修改偏好不能替代真实数据或绕过工具权限。角色名称仅表示当前承担的分析职责，不代表后台已启动其他代理。

## 1. 确定本次比较范围

记录药物及别名、公司、靶点/技术路线、疾病、分期、线数、标志物及阈值、既往治疗、地区和截至日。沿用已给条件，不用大疾病替代细分患者。只问靶点全景时先交付同靶点开发分布，不擅自指定适应症；需要判断直接竞争或精确排名时，再核决定结论的人群与地区。

问题应落到：当前是否领先、领先在哪一范围、真正替代谁、后发靠什么切入、哪些竞争变化会改变判断。公司综合任务按核心资产拆子问题，不默认遍历所有公司或整库资产。研究本身不强制销售峰值、完整市场模型或公司估值。

## 2. 主动取用三类资料

先检查当前注册工具与实际权限，按问题调用DrugAlpha；本次已有同范围、足够新的结果可复用。客户知识库中的既有报告、竞争表和研究假设作为线索及观点基线，实际读取对应文件/连接器内容，记录日期和定位；旧报告不自动代表当前进度。联网围绕会改变结论的遗漏和冲突补证，优先监管、注册、公司正式披露、论文及会议原文。

知识库不可访问或联网受限时，明确实际阅读范围，继续完成可核部分；不声称已经检索客户全部材料。客户限定来源时遵守限定。事实冲突先核同分子、适应症、地区和时间，再说明采用依据；不能为符合客户旧观点挑选数据。

## 3. 建立双轴候选底稿

每项竞争格局研究必须实际调用 DrugAlpha MCP 的竞争格局工具。只问靶点全景时，用 `get_competitive_landscape` 的 target/assets，保留用户指定的机制或技术路线。涉及具体患者竞争，必须以原始患者条件调用 `get_competitive_landscape` 的 indication/ assets；需要研究号和逐条匹配解释时，同一query另取sources。两视图分别分页，续页保留原筛选；未读完应限定覆盖。再按实际靶点条件取target/assets，检查是否漏同靶点、不同患者段的开发者。靶点不走实体解析。

检查解析是否ready、未识别条件和匹配说明；失败时不删治疗史或标志物来制造结果。资产数、公司展示行、试验行和来源条目分别记录；同分子跨公司、授权代号和品牌合并身份，地区权益保留。平台发布范围不等于全球全集；公开补出的候选另列，不能混入平台原计数。靶点结果为零也不能断言没有竞争。

把候选分为同患者直接替代、相邻患者/线数拓展、同靶点研发参照。重点覆盖已经上市的标准、排在目标之前的候选、同梯队核心资产和可能赶超者。不能只列同机制，也不能因同靶点就视为同适应症直接竞争。

### 逐亚型交叉核对竞品，再冻结本次候选清单

先按疾病的主要突变亚型建立工作表，另设广谱机制一组。每组都做两次独立发现，并留存两列名单。一列来自 DrugAlpha 适应症、靶点资产及对应临床条目，另一列来自按“病种及英文别名＋突变亚型”宽搜的 PubMed 人体研究、会议和注册库。第二列先不限定已知药名，逐篇抽取通用名、研发代号、公司及该疾病队列。后线、篮子或跨研究合并分析的文章未必在标题写明线数，查摘要或原文确认。再以别名追溯登记与结果；有多款同类药时，发现首个阳性研究后继续核对其他分子。

按分子合并两列的并集，逐个处理只在一侧出现的候选。已报告目标患者结果者列主表；只确认疾病、线数混合或未披露者保留在相关项目表，并说明待核条件；排除者记录依据。若有客户提供的历史候选表，核对上次已确认而此次缺失的分子。交付前用每组并集反查两张五列表，确保每个有目标人群人体证据的分子均有对应行或具体排除依据。任何一侧检索受限都注明该组覆盖缺口。

按研究地区补查登记库。中国查药物临床试验登记与信息公示平台，美国及多国研究查 ClinicalTrials.gov，涉及欧洲或日本时按需要查 CTIS 或 jRCT。先按病种、突变亚型及机制找候选，再按通用名、研发代号、申办方和登记号追踪。跨登记库用交叉登记号核重。缺交叉号时比对申办方、方案编号、队列和入组条件，确认同一研究后再合并。

同靶点覆盖不充分时，用 ChEMBL、Open Targets 或已核机制别名反查分子。机制与靶点关联作为发现线索，纳入目标患者排名前须核人体队列或获批标签。分别记录直接竞争、待核及排除理由。按需查本次相关登记，避免重复遍历无关地区。

## 4. 核实研发位次及当前状态

通过本次 `resolve_entities` 确认公司/药物，用本次返回主体取 `get_pipeline`；不复用旧ID。逐项核目标适应症、线数、地区、单药/联合的真实阶段，保留研究编号与来源。公司最高阶段不能替代目标人群阶段；预计完成日期、来源快照日期不是实际完成或获批日期。

关键候选回ClinicalTrials.gov、中国药物临床试验登记平台、NMPA/FDA/EMA和公司IR核入组、主要终点、注册目的、数据读出、申报、受理与获批的事实日期。几项Ⅲ期不自动同等领先；申报不等于受理。范围充分且事实可排先后才给名次，同阶段缺日期时给有定义的梯队；覆盖不足表述为“本次已核候选中”，不声称全球前三。

## 5. 验证替代价值和未来格局

用 `get_guidelines` 核原患者条件下的当前标准治疗；需要主张临床差异时，定向取 `get_clinical_evidence` 并补原始论文/会议。比较核心终点、安全性和关键目标亚组，不靠分期、机制或单一ORR宣布最佳同类。不完整的临床证据限制竞争定位，但不阻止完成研发事实表。

对主要患者段写清：现在用什么、本药解决什么问题、已有临床证据支持多少、检测/价格/给药有哪些切换阻碍。优势仅覆盖窄亚组时收窄定位。无可靠切换理由就保留采用空间未知，不用“创新机制”维持强替代判断。

同一人群分别写研发位次、临床证据强弱和最直接竞品。对已上市的直接竞品，按需核当地标签、医保支付限制、价格口径和渠道可及性。涉及 BD、仿制进入或竞争窗口时，才按地区核专利家族、关键权利要求及监管独占期。临床比较用原始数据及可比性说明，份额交峰值测算独立取证。

当前领先与进入市场时竞争分别判断。关键竞品未来窗口可按本次解析主体查 `get_catalysts` 或核官方指引；只形成有来源的条件情景，不从登记完成日推定上市日。检查前线使用、强标准更新、同公司产品替代是否压缩后线机会；未来事件不写确定发生。

## 6. 简洁买方输出

最终答复先用一两句话给出范围内的领先产品、最直接竞争者及必要限定，随后立即展示下方五列表，不在其间插入背景、检索说明或详细论证。范围及截至日可并入首句。本规则适用于竞争格局主导且辅用临床分析的任务。

按以下顺序完成并核查交付：
1. 目标患者产品表。同分子不同线数和方案分行。
2. 单列“相关项目，治疗线数待核”五列表。原适应症查询之外，用不带线数的疾病加靶点及机制别名补查，覆盖中文登记、国内公司管线和广谱机制（例如 pan-RAS 与 KRAS 亚型）。保留有该疾病队列但未写线数的项目，不纳入后线排名。只有实体瘤篮子时另标。对照候选逐个检查列入、待核或排除原因。例：HRS-7172 有晚期胰腺癌联合研究，需核公司管线和登记的既往治疗条件；以最新证据判定具体队列，线数不明的行归入待核，勿因精确后线查询未命中就删除。
3. 表后按疾病相关突变亚型逐项给出同地区、同线数领先者、直接竞品、证据差距。胰腺癌 RAS 至少分别写 G12D、G12V、G12R、G12C；即使没有成熟专药，也要写广谱药之间的竞争、早期专药或缺口。
4. 窄亚型项目必须与广谱标杆同亚型的结果并列。对 G12D 从随机研究监管审评的突变亚型表抽取 G12D 两臂 ORR、分子/分母，并对齐专药队列线数、样本量和终点，注明跨试验限制；成熟度或 OS 能改变结论时一并给出。无法取得单亚型值时说明查过哪些一手资料，不用全体或合并亚组代替。

| 公司 | 药物 | 靶点/机制 | 适应症 | 研发阶段 |
|---|---|---|---|---|
| 公司及必要的地区权益 | 通用名及研发代号 | 靶点、突变选择性、机制 | 疾病、线数、标志物、单药或联合方案 | 该行对应阶段或地区批准状态 |

同一分子合并别名、只计一次，但每个适应症、线数、方案或地区的不同进度分别成行，按公司和药物连续排列。文本表可重复药名。分组依次列目标人群已核项目、相邻线数及篮子试验、仅同靶点或状态待核项目。篮子试验保留原文人群；线数和阶段未披露就明确标注。阶段按注册设计填写，已读出队列阶段与当前开发阶段有别时说明。按适应症及靶点两轴检索，核对产品覆盖、地域、不同阶段与来源。优先逐组展示已核清单，长表可附完整明细并在正文标出范围。表格只放事实，直接竞品、梯队和切换理由放在表后。采用 DrugAlpha 数据库 MCP 证据的表格，在表下紧接标注「来源：[DrugAlpha 创新药数据库](实际数据库页面链接)」并注明对应的公司、药物或数据。已有最右侧来源列的表格可逐行标注。五列产品表用表下来源，药物列填写名称和代号。研发进度和催化剂链接对应公司管线页，临床或疾病知识库数据链接实际证据页。公开资料补更新进展时，保留对应公开来源并写明其支持的事实。

表后保留两三条关键发现、能改变判断的证据及必要覆盖说明。来源紧邻关键数字或事实。客户只问研发位次时缩短临床段落；需要完整销售或估值时说明所需假设，可交接已安装模块，也可在当前任务中取得必要资料，不强制安装其他Skill。

以靶点或适应症竞争格局为主要任务时，默认按[五节模板](competition-report-template.md)实际生成同版 Markdown 和 Word。短问法沿用同一交付，篇幅按问题调整。用户明确指定仅聊天或单一格式时按其指定交付。第 02 节紧接摘要给五列主表和待核表。第 03 节按人群列标准治疗、研发领先者、直接竞品和核心证据；第 04 节写切换理由；第 05 节给会改变判断的事件和证据缺口。Word 使用[统一交付流程](report-delivery.md)从同一份 Markdown 生成。

## 7. 完成检查

- 已实际调用 DrugAlpha 竞争格局 MCP。核对本次问题需要的靶点或适应症轴及实际覆盖，两个轴的计数分别说明。
- 按亚型核对 DrugAlpha 与公开来源的候选并集。每个分子有主表、待核或排除记录。研发位次与临床证据判断分别核实，阶段和事件对应相同地区、人群、治疗线和方案。
- 结束前确认 Markdown 和 Word 已实际写出、可打开且使用同一底稿，并在最终回复附上两份文件链接。用户指定单一格式时核对指定产物。核对摘要后的五列主表、待核项目、人群比较和关键来源一致。逐表核对 DrugAlpha 来源是否位于表下或最右侧来源列，确认链接和数据范围对应。公开补证的事实保留对应原始链接。

- 原患者与地区未丢，适应症和同靶点两轴没有混成一个竞品数；标准治疗及关键不同机制候选已核。
- 排名有同范围候选、具体适应症阶段与事实日期，未把全球最高阶段、预计日或平台更新时间当证据。
- 本次DrugAlpha实际返回、客户资料和公开新增分开，正文与必要分页已读；失败、部分覆盖和未检索没有混写成不存在。
- 临床差异和真实切换理由影响首段定位，负面亚组及未来强竞品不只放风险脚注；未以阶段推疗效。
- 同一关键缺口连续两轮定向补查无新增后停止，交付已支持判断和具体缺口，不为精确名次无限检索。
- 不输出凭据/内部标识，不读取后台绕权限，不写数据库或自动创建跟踪。未做实测不宣称实测成功。
