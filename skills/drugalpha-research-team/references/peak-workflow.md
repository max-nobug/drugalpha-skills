# DrugAlpha销售峰值测算：执行流程

## 服务场景

- **投资研究**：测算分地区和适应症的年度销售、峰值及关键敏感性。
- **BD 决策**：按拟交易地区和权益测算销售潜力，为分成、供货及其他交易情景提供输入。
- **医学事务竞品分析**：量化各竞品覆盖的患者群体及治疗路径中的切换空间，区分临床证据和采用假设。
- **医保谈判证据准备**：整理参保适用人数、纳入后的用药比例、疗程与费用，测算可复核的预算影响情景。销售峰值与医保基金预算影响分别列示，后者明确支付方、替代治疗和支付口径。

回答具体产品在明确地区、适应症和时间条件下，最高可能形成多少年度销售，哪些假设决定结果。可独立完成，不要求安装竞争、临床、催化剂或估值Skill；已取得的合格研究直接复用，否则自行核必要依赖。调用细节见[竞争格局与销售峰值共用 MCP 指引](competition-peak-mcp.md)，来源与冲突处理见[证据规则](evidence.md)及[客户资料接入](sources.md)。客户偏好见[研究配置](preferences.md)，不能以偏好替换事实。

## 1. 先固定对象与测算含义

确认药物及别名、目标地区、适应症/线数/标志物、单药或联合、证据截至日、预测年度和所需币种。区分四项：市场总规模、可及市场、具体产品销售峰值、公司可归属收入。未上市资产默认给“获批且达到所列临床/准入条件”的销售情景，不把它当确定预测，不凭临床分期自动赋成功率，不以峰值乘PS冒充公司估值。

关键未知可保留变量，先完成不依赖它的研究。未明确获批范围、价格或份额时，给可复算条件区间，不为出一个数而编假设。区分成熟年度的稳态潜力与预测期间内可达到的最高销售；未建年度路径不能给确定峰值年份。

## 2. 数据取证顺序

逐项执行[药物销售及 DCF 参数的第一数据源](competition-peak-mcp.md#药物销售及-dcf-参数的第一数据源)，用实际 DrugAlpha MCP 返回建立参数底稿，单项无可用依据时才联网补证。按患者分母、临床定位、竞争、可比药费用和上市节奏逐项记录“平台实际取得 / 原条件未命中 / 公开补证 / 自主假设”，在 Excel 的来源栏区分。对已正确解析但无匹配的精确人群，保留原结果；另查疾病＋线数作为邻近证据，逐条核原始适应症、突变亚型、疗线、别名和队列，再决定能否用于本题。解析未就绪则先澄清。指南中的其他突变不可外推为目标亚型推荐。

对影响结果的月净价和上市时序，优先尝试平台可比药价格、说明书与治疗费用口径，以及相关管线和催化剂；注明实际取得值和局限。读取客户的规格选择偏好。客户已授权自动选择时，按通用名、剂型、说明书剂量、地区及价格日期核对，优先选包装数量和金额明确、能复算日剂量的一种，记录所选规格、依据及其支付口径，直接折算足年及月均费用。发现候选与说明书不符时另选可核规格，仍无法核实则标记缺口。公开支付标准与本品净价分开。可比药折算月费按来源原值作为基准代理，明确是医保支付、挂网或其他价格口径。产品净价或逐年降价只有在同市场的实际结算、可比产品支付变化、渠道或竞争证据支持时才能调整。缺证时沿用参考价作同价情景，折扣单列敏感性并标注假设。独立测算后的公司估值仅作口径对照。上市后的真实采用和未上市净价无可验证来源时保留假设。验收时对照关键参数逐项找平台遗漏，不以调用接口次数代替实际使用。

1. 发现当前DrugAlpha工具及权限，复用本次同条件有效返回。确定产品全范围时，在管线之外实际查询相关公司及地区权益合作方的催化剂，包含时间未定事件，并回公司或合作方披露核实具体瘤种、疗线、地区和拟启动/读出/申报节点。明确开发计划的适应症纳入测算。尚未进入注册阶段的项目按成功条件情景逐项计算；联合方案属于同一患者池时建竞争或替代情景。证据只有探索性信号时列待核，并核是否已有后续开发计划。用户明确限定某一适应症时，在范围外提示新增计划。公司/药物主体需要时先`resolve_entities`，后取`get_pipeline`核目标适应症进度；药物全局最高阶段不替代该地区该人群阶段。
2. 以原始患者条件查`get_competitive_landscape`的适应症资产，必要时同条件取sources及同靶点补充。核真正竞争、进入市场时的先后和切换理由；需要临床定位时自行取`get_clinical_evidence`、`get_guidelines`及匹配标准治疗，不因未安装其他Skill而停止。
3. `get_epidemiology`先完整读目录，再用本次返回主题标识读正文。原文统计年、地区和分母保留。简单药名直接用`get_overseas_drug_sales`查可比产品；复杂多药/地区筛选才读该销售目录。金额依返回单位，百万美元转亿美元除以100；品牌合列不拆、地区重叠不加，海外年度不是国内或季度数据。
4. 仅在用户明确要求与旧模型对账时，先完成独立基准并记录全部输入、结果及依据，再，名称直查`get_company_valuation`。该公司个人模型优先，保留删去/排除项、来源和日期；个人读取失败不自行回退平台。原峰值及概率只是原模型假设，列“原假设—新证据—本次情景”，不把它当实际销售或市场容量，不写回。
5. 按[客户资料接入](sources.md)检索本题相关的已授权报告、访谈、模型和历史观点，保留文件定位及日期。用客户实际输入承接研究偏好，但核其分母、价格及权益来源；未连接不能称已检索知识库。
6. 缺口定向联网：国家癌症登记/IARC/人群研究核患者；监管标签/指南核范围；公司财报、IR及原协议核销售和权益；试验注册/论文/会议材料核治疗定位。关键结论回一手正文，客户旧报告与数据库冲突时查期间、定义和原始来源，不机械选高值。连续两轮对同缺口无新增即停并说明。未匹配不能删人群条件放宽后冒称原条件已查到。

### 临床空结果：同义词归一、扩大检索、逐条核入组

精确条件解析成功但未命中时，不能直接判断平台无数据或跳过平台转用网页。保留原查询与其结果，按以下两步回退；最多两轮，无有效新增即说明覆盖缺口并联网补证。

1. 第一轮做疾病及疗线的同义词归一：例如“经治／既往接受治疗／二线及以后”可用于检索“后线／2L+”相关记录，但它们并非严格等价的入组条件。依据原问题生成规范疾病名＋疗线查询，不将药名用作适应症查询；同轮检查解析是否正确、必要分页是否完整。
2. 仍无有效记录，第二轮扩大为疾病＋疗线（去掉检索中的标志物限定），必要时疾病级检索并在结果中筛选药物及本次已核别名。扩大的是召回范围，原问题的疾病、标志物、线数和方案约束保持不变。不要反复用同一种措辞重试。
3. 对召回候选逐条核药物及别名、疾病/组织学、突变亚型、既往治疗及实际线数、单药/联合、剂量队列、分析集、截止日期与随访成熟度。分为“直接适用／仅邻近参考／条件不明待核”；扩大查询的总计数不是本题适用记录数。条件不明回原论文、会议、注册或公司披露核实；不能把泛突变、混合瘤种、一线数据冒充目标亚型后线证据。
4. 总体与分层数据并存时，按目标线数使用；二线、三线及以后与混合后线分别保留。mPFS未达到不能填成总体已达到值；记录成熟度并单列疗程代理假设。DrugAlpha已有可用记录时必须进入临床与疗程底稿，联网只补缺或校验更新；出现冲突查清队列、时间与定义。
5. Excel来源栏保留取得途径、适用人群、原始数字及引用；未命中只表述为“本次这些查询未召回”，不能断言数据库没有。内部验收记录原查询、回退查询和候选纳入/排除依据，正文只展示结论和关键证据。

## 3. 建立患者与销售模型

优先采用直接披露的细分患者数。展示发病/复发流入、目标病理及突变、实际进入该治疗线、检测覆盖、支付可及、实际用药各步的绝对人数和累计保留比例。核对来源分母是全部晚期、已开始一线还是已检测人群；有地区、癌种和疗线匹配的真实世界人数时做独立对账。使用已进入某线的直接人数后，同一治疗脱落不再重复扣；基准与敏感性分别验证无证据的漏斗系数。发病基数按其原统计年份向模型年外推，分开核查复发流入和既往暴露去重。需要推算时，分别列来源或自主假设、条件分母、地区和年份，示例结构为：年度进入目标治疗路径的人数×检测/适用比例×实际可及比例。疾病人数不能自动成为NSCLC、特定亚型或后线患者；后线应核到达该线的流入与脱落。相同检测、可及或支付限制只扣一次。

分别处理年度新发、复发流入、既往积压及跨年在治患者，积压释放不能永久计入稳态新流量。不同适应症、线数、联合方案和本公司产品间核患者重叠及自我替代；不能把宽适应症销售按未经证实比例拆成目标适应症。

价格与暴露按收费方式选择，不套统一年费：

- 持续用药：各入组月份/年度队列在当年形成的患者月×每患者月净产品收入，再汇总年度销售。若用稳态年度流入×平均疗程费用简化，说明稳态假设，不据此推首年销售。
- 固定疗程/按剂收费：当年实际付费疗程或剂次数×对应净价，核疗程完成、负荷维持及折扣，避免用终身药费乘当年新发冒充年销售。
- 一次给药或成果付费：按当年治疗患者及实际付款安排建现金/收入路径；治疗数、开票或收款不自动等于当年会计收入。

净价、体重/体表面积、给药频率、包装换算、剂量强度、休药和停止条件有依据才落值。肿瘤药按持续给药测算时，优先用同线同人群实际用药时长、停药时间或真实世界付费患者月。若缺失，且方案通常用至进展，可用同方案、同线同亚型的 mPFS 作为疗程情景的起点。记录数据截止、成熟度、中位数口径及提前停药、进展后继续用药、赠药等调整依据。中位 PFS 不能直接证明平均付费月数；缺少校准资料时明确标注代理假设并做疗程敏感性。固定疗程按实际给药计划和完成率估算。

同类药优先选同市场、相近适应症及支付环境的产品。通过 DrugAlpha MCP 取说明书、已确认规格价格和治疗费用框架，在 Agent 端按剂量、频率和包装算出足12个月的药品费用，再除以12得到月均费用。Excel列示可比药、规格、剂量、地区与价格口径、年度费用、除以12的公式及来源，再单列本品采用的月净价及调整依据。若原年费已按短疗程或停药概率折算，按对应付费月数求在治月费，避免将年费除以12后再乘短疗程而重复扣减。负荷与维持价格差异明显时分别计算。 需查说明书、价格、费用框架时用相应MCP；价格候选的具体药品规格须已确认，挂网/支付标准不是企业净价。未上市无实际价格，情景输入明确标“假设”。联合方案只计本产品销售，不把伙伴药费用算入。

### 患者流明细与方法选择

根据研究问题、疾病治疗路径、收费方式和证据选择主模型。若有可靠的目标人群年度流入、平均疗程和稳定份额，可估成熟期销售。若要判断上市爬坡或峰值年份，逐年建模；当复发时滞、前线治疗变化、跨年在治或停药显著影响销售时，按队列计算各日历年的患者月。已上市产品也可用可核实的实际销量或销售额作起点。

从宽人群推算后线患者时，分别核新发晚期、复发流入及前线脱落，说明何时进入下一线；若已取得同口径后线人数，直接使用，避免重复加减。续治贡献患者月但不重复计为新增患者。例：去年12月启动、今年续治3个月，今年计3个患者月。证据不足时保留区间，并说明对峰值的影响。

可借鉴 DCF 的患者流计算结构。治疗费用、付费疗程、渗透率、份额等全部独立取证设定，旧模型数值不能作默认值、区间端点、锚点或缺数回填。可比药月费用从已确认规格、实际给药方案及当地价格口径推算，再说明本品净价假设的折扣与限制。付费时长优先查实际用药、停药和持续治疗数据。采用与份额结合可比药真实采用和同线竞争判断。每个关键输入注明事实、推导或情景，以及改变区间的证据；无法支持点值时保留区间或变量。

## 4. 份额、年度爬坡与权益

每个地区、适应症、治疗线数及关键亚组分别建模，先定分母，再估两层采用：①疗法类别渗透率＝使用该类疗法人数／对应可及患者数；②产品在类别内份额＝使用本品人数／使用该类疗法人数。若已直接估出本品占可及患者比例，只乘一次。联合治疗按方案和唯一患者计数。先计算各适应症销售，按权益及重叠检查后汇总；各适应症占产品销售的比例是结果。禁止为达到预设销售额或匹配现有DCF而分摊适应症销售、倒调渗透率、份额、疗程或净价。
优先以同地区同线实际用药人数、处方或有明确定义的份额起算，说明其分母和日期。未上市时用可比药上市后的真实采用曲线作区间参照，再按与标准治疗及直接竞品的临床差异（核心终点、安全性、便利性）、患者切换理由、上市时序、医保及医院准入逐项解释调整方向和幅度。列“依据—适用差异—假设区间—会改变区间的事件”。疗效优势不能机械换算成份额百分点；资料只支持方向时给条件区间或保留变量。各情景先改能观察的竞争条件，再重算销售。
对产品整体采用或类别内份额分别明确所选分母，解释临床差异、先发窗口、检测、准入、支付及竞争者进入如何影响采用。按细分人群分配时总采用不能超过同一患者池；同靶点资产数不直接换成平均份额。所谓“创新”“更早Ⅲ期”不能支持任意高份额。

建立逐年患者、可及、采用、净价、治疗暴露及销售路径，注明上市/准入/竞品窗口的来源或假设。保守、基准、乐观情景围绕真正关键变量展开，并考虑价格下降、后续竞争、专利或供应限制，不仅同步扩大所有输入。年度峰值为所设预测期间内年度销售最大值，列对应年份；路径不足则只给成熟期条件区间。

产品终端销售与公司收入另表桥接。按地区自营、供货、分成或版税及合同计价基础处理，不能用一个“权益比例”代替所有商业模式；里程碑、首付款不混入产品销售峰值。注明币种、汇率日期/假设及财年起止，不把全球与地区、合作双方或财年与自然年重复加总。

## 5. 外部对照、完成条件与简洁输出

独立测算完成后，如用户询问某外部预期隐含什么，可另列其所需治疗人数或份额，与原预测并排。只有总销售额且适应症或多个参数同时未知时，没有唯一解。标明“外部目标隐含条件”，不得回填基准情景；预测仅因独立的新证据而修订。同类实际销售用于合理性校验，需说明地区、适应症、上市年限和品牌范围。关键参数缺失只给变量关系或条件范围，不凑确定峰值。原预测上修或下修须能追溯到输入和理由。

每次以销售峰值测算为主任务时，按[五节模板](peak-report-template.md)交付同版 Markdown、Word 和可复算 Excel。Word 用统一渲染脚本的 `--kind peak`。除用户另有指定，完成回复附三份实际生成的文件。

**复用 DCF 单药页。** 从[康诺亚版式的 DCF 工作簿](../assets/dcf-valuation-template.xlsx)复制「国内药物」作为通用药物页原型，复用第 6–16 行的横向患者流、价格、疗程和逐年终端销售结构以及上市年引用。保留配色、字体、冻结及右侧「说明」「来源／依据」。把可编辑的情景、患者、费用、汇率和地区折算参数集中到「测算假设」页，地区页引用该页，只展示计算与结果。将估值专用行替换为有依据的峰值输入、分情景比较与汇总所需行。用同一患者基数和公式交给下游 DCF，适应症或范围不同时交代差异。 工作簿生成命令为 `python scripts/build_peak_sales.py inputs.json output.xlsx`，依赖为 `openpyxl>=3.1,<4`，安装与检查见 [Skill 入口](../SKILL.md#生成文件前按任务检查-python-依赖)。输入格式见[峰值工作簿输入说明](peak-workbook-inputs.md)。

**地区独立测算。** 每个实际纳入的地区建独立页，页内按适应症、疗线、标志物和用药方案分块。患者、支付、同类药渗透率、本品同类份额、上市年、疗程与当地币净价分别取证和输入。测算海外时默认沿用 DCF 口径，美国独立测算，欧洲每年为美国当年终端销售的 50%。地区汇总、海外测算页及 MD／Word 正文均合并展示「海外」销售（美国加欧洲），在表下注明计算口径。海外患者、渗透率、份额、价格及疗程为美国测算基础。用户明确要求欧洲独立测算时，按当地资料建模。数据不足时标明条件和证据缺口。多地区汇总按同一日历年将当年地区销售换成同币后相加，再求合计峰值。各地区分别显示本币峰值、年份及覆盖范围。

**计算与验收。** 终端销售在成功商业化条件下按年度计算，分成和概率仅在另行要求的归属桥中出现。按地区和人群直接取证，用药物竞争格局和临床差异解释假设，禁止用平台或目标销售额倒推。涉及本药跨线重复使用时只扣有理由的本药重复暴露；按场景单列假设。逐年按本品新用患者×全疗程费用估算时，注明新启动患者完整疗程的销售归属近似；跨年对峰值年或首年有实质影响时补当年实际付费暴露队列。末年仍在增长时列「预测期内最高值」，有依据才另列成熟期。调整一个关键上游输入并复算，验证患者、年度销售、地区与合计峰值联动。核对报告、Excel 和来源链接一致，实际缺口留空并说明。
